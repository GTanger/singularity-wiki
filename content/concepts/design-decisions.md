# 設計決策與原則

> **奇點世界**（Singularity World）設計決策彙整。本頁記錄專案為什麼做某些取捨，供快速查閱「我們決定了什麼、為什麼」。

---

## 一、設計關鍵字與哲學

### 核心命題

**從有限框架延伸出無限可能。**

本質是將文字 MUD 搬上手機，省略一切指令輸入（改為指觸操作），用萬名以上異步、多差異個性 NPC 把世界撐滿、撐出生命感。

### 設計支柱

| 支柱 | 要點 |
|------|------|
| **深度沉浸** | 重體驗、輕操作；重文字、輕畫面。Top-down 視角，字符示意地形，人形生物以「圓＋一個中文字」呈現 |
| **後端唯一真理** | 前端僅是顯示窗口；所有判定、結算、數據皆在後端。前端不得猜測、不得改語義 |
| **玩家＝NPC** | 不因身份區分規則；玩家下線後角色變為在線 NPC，執行離線前設定的簡單任務 |
| **不可無中生有** | 思維邏輯閉環、永序守衡。物件不可憑文字創造，技能不可憑空發明 |
| **觀測與坍縮** | 視線未及之處 NPC 處於多重疊加態故事線；玩家觀測到則坍縮為單一現在態；實際接觸則連過去態也坍縮 |
| **沃土風（非廢土）** | 環境富態生長、靜謐豐饒，但豐饒≠安全——萬物皆哺亦哺，強競爭與掠食 |
| **世界就一個平面** | 無室內、無進出建築切換；功能建築接觸後點擊提供交互選項，非功能建築為擋路實體 |

### 已決斷的補充設計方向

經關鍵字完善度評估（KEYWORDS_ASSESSMENT），主管對以下區塊做出決斷：

| 區塊 | 決斷 |
|------|------|
| **經濟** | 單一貨幣產消閉環＋時間綁定產出（A＋E） |
| **死亡** | 無永久死亡、狀態懲罰，可選死亡後短暫離線化（A＋部分 B） |
| **時間** | 世界時間加速（有晝夜／季節）＋後端事件時間軸（B＋C） |
| **同服互動** | 可交易＋可合意對戰＋可組隊共鬥（B＋C＋D） |
| **物件粒度** | 向量／形狀碰撞＋物件類別明訂（C＋D） |
| **自創技能** | 組合既有模組＋配方藍圖＋提案驗證＋熟練度延伸（A＋B＋C＋E） |
| **敘事呈現** | 分頻道 log＋常駐 log＋可展開情境＋log＋重要事件彈窗（B＋C＋E） |
| **新手引導** | 無教學，出生即進世界（A） |

## 三、展開各 ADR

### ADR-001：戰鬥規則統一

- 不論對戰組合（PvE / NPC vs NPC / PvP），皆走**同一套判定、屬性結算、戰鬥 log 語義**
- 後端不因實體是否為玩家而走不同分支；僅區分「攻擊方／防禦方」
- 戰鬥全自動、文字 log；輸贏靠裝備與技能的數據配置（田忌賽馬概念）
- 前端不得預測勝負或改動後端回傳的戰鬥敘事語義
- 對齊插頭／插座設計：Attack 為插頭，目標需具備 `[Agent]` 插座

### ADR-002：插頭／插座語義

- **插座**＝可互動對象對外開放的可執行動作清單；**插頭**＝玩家或 NPC 的意圖（動詞）
- 後端收到「動詞＋目標」後檢查插座匹配，匹配則執行並回傳結果，否則回傳不可執行
- 名詞語義分四類：Agent（活體）、Structure（建築）、Item（物品）、其他可互動物件
- 動詞包含 Attack、Talk、Take、Drop、Trade、Examine、Craft、Operate 等；**不含 Enter**（本專案無進出建築）
- 前端禁止自行列舉可用動詞；一律依後端回傳的清單顯示

### ADR-004：技術棧與架構

- 後端 Rust（Axum + Tokio），前端原生 HTML/CSS/JS（PWA，開瀏覽器即玩）
- 持久化權威為 PostgreSQL；JSON 僅用於種子匯入、靜態設定、可選備份——禁止新增「只寫 JSON 不落庫」的資料路徑
- 九萬 NPC 平時不跑，只存狀態＋上次觀測時間；觀測時從事件日誌回推（延遲坍縮）
- 視野內（同房）NPC 才進入即時模擬；全域系統（經濟、政治、生態）持續背景 tick

### ADR-005：空間單位與視野（房格一致）

- 格子、房間、視線所及三者為同一概念的不同表述
- 玩家在某一格即在某一房，視線範圍即該房間；無跨房視線
- 決策 004 的「視野內即時模擬」以此定義為準——與玩家同房的 NPC 才即時模擬
- 若日後擴充 2D 俯視地圖，一格與房間仍可 1:1 對應

### ADR-006：登錄與玩家模板

- 先做登錄（識別「誰在連線」），再做玩家模板（創造角色）
- 玩家與 NPC 共用同一套 `entities` + `entity_room` 結構，以 `kind` 欄位區分
- 第一版採「id＋密碼」方案：創角時設定，之後開網頁即為登入表單
- 密碼僅存雜湊（bcrypt），獨立 `entity_auth` 表，與 entities 分離

### ADR-007：NPC AI API 與預設使用規則

- **預設**：所有 NPC 所有行為一律走模板／規則邏輯
- **例外**：僅當「玩家對單一 NPC 的 Talk」且「該 NPC 被允許使用 AI」時才呼叫 AI API；失敗或超時一律 fallback 預設
- 本地小模型（2B~4B）可作為 AI 後端；關鍵 NPC 用大模型、路人用小模型
- 對話池兼作 AI 提示素材與 fallback 來源，不需維護兩套口吻

### ADR-008：架構整頓規劃

- 已完成：拆出 `npc/` 子系統、清除 SQLite 殘留、handler 按職責切分、docs 重新分區
- 架構契約：執行期僅經 `store` 存取；`db` 為 store 的業務封裝

### ADR-009：觀測分級與行程約束

- **單一世界時鐘**全域推進，觀測分級只改變敘事與推理成本
- 行程（上班、在崗、睡眠）為**硬約束**，優先於擲骰
- 在崗與在場由權威資料（排班、店舖狀態）決定性解析，不以隨機決定
- 觀測四層級：無觀測→同畫面→注視→對話
- **世界在暗處仍依規律活著；鏡頭照到時，才把話說得像人**

### ADR-010：Go → Rust 遷移

- 後端從 Go 全面遷至 Rust（Axum、Tokio），已落地
- 核心理由：以編譯期型別檢查取代慣例約束，降低代理實作時的隱性錯誤面
- 詳見 → [[concepts/rust-migration|Rust 遷移決策]]

## 四、協作約定

- **負責人＝主管**，**AI＝組員**。主管為最高意志，所有設計取捨由主管決斷
- 組員主動依既有知識提出想法、選項、風險與參考；不待被問才答
- **地基優先**：最小版本是妥協非理想——在可行且不阻礙驗收前提下，優先把設計與架構做穩
- AI 不代為做最終決定；採納與否由主管定

## 五、技術約束規則

### 程式碼風格

- 每個函數開頭必須有**中文註解**（做什麼、吃什麼、回什麼、副作用）
- 單一函數不超過 **50 行**；巢狀不超過 **3 層**
- 單檔不超過 **300 行**，一個檔案只做一件事
- 禁止 `init()` 函數；所有錯誤必須明確處理

### 禁止事項

- 禁止產生框架式空殼程式碼（不可生成 TODO 或 placeholder）
- 禁止未經討論就改變資料結構
- 禁止在程式碼中硬編碼遊戲數值（可調參數必須集中管理）
- 不得自行引入新依賴或刪除／重構既有程式碼，須先提出理由
