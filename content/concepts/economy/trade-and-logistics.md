# 交易與世界物流

> 本專案以**世界物流**為單一概念框架，涵蓋一切「從 A 到 B 的流動」。Trade 為物流之交換介面。

## 世界物流：單一概念框架

「物流」在此為廣義的**流動 (flow)**：任何主體所擁有的客體，從來源到去向的移動或轉手，皆屬之。好處：

1. **單一詞彙**：不必並列「經濟系統」「交易系統」「物資系統」「人流系統」
2. **規則一致**：產出／消耗／轉手都遵守「有來源、有去向、可追溯」，與**永序守衡**、**Stuff in ~ Stuff out** 一致
3. **實作邊界清楚**：Trade、移動、採集、店舖庫存、機構發放／回收、背包，都是物流的介面或節點

## 六大流動類型

| 流動類型 | 主體 | 客體 | 來源／去向範例 |
|----------|------|------|----------------|
| **物資流** | 實體、場所 | 物品 | 採集->背包；製造->背包；買賣->轉手 |
| **金流** | 實體、機構、場所 | 鎂 | 任務->實體；交易->買方<->賣方；據點稅->機構 |
| **詞元流** | 實體、機構、場所、世界詞盤 | 詞元（含鎂字、結晶） | 剝名->詞元；入竅/附魔->消耗；祭煉->登錄 |
| **人流** | 實體 | 實體自身 | 排班->房間；尋路->房間；遷移->房間 |
| **服務流** | 實體、機構、場所 | 勞務／服務 | 排班工作；任務委託->報酬；附魔/傳送->花鎂換服務 |
| **資訊／事件流** | 系統、實體、場所 | 事件、敘事、記憶 | 事件日誌->實體；narrate->房間；戰報->玩家 |

### 流動間的關聯

- **物資流**與**金流**常一起發生（Trade：一手交錢一手交貨），建模上可分開
- **人流**決定「誰在哪裡、誰能對誰做 Trade」；在場決定可執行的插座
- **行腳商**身份由「有貨 + 移動 + Trade」湧現，無須另設職業

## 世界物流規格 `定版`

### 物資流

| 項目 | 規格 |
|------|------|
| 物品資料模型 | id、name、stackable、歸屬（實體 vs 場所） |
| 來源 | 採集、製造、任務、初始配給 |
| 去向 | 消耗、損壞、交易轉手、sink |

### 金流

| 項目 | 規格 |
|------|------|
| 鎂轉手 API | TransferMagnesium；與 Faucet/Sink 對齊 |
| 交易原子性 | 買方扣鎂、賣方加鎂同一原子操作 |
| 記帳 | 可選，實作時決定 |

### 詞元流

| 項目 | 規格 |
|------|------|
| 資料模型 | 依[[wordplate-system/index|詞盤彙整]]、機構賦權討論稿 |
| 消耗規則 | 入竅、附魔、祭煉、登錄 |
| 可交易者 | 結晶或附詞裝備 |

### 服務流

| 項目 | 規格 |
|------|------|
| 排班工作、乞討、任務報酬 | 依現有設計 |
| 附魔／登錄／傳送 | 花鎂或行為換取服務 |
| NPC 代為 Trade | 權限 = 在場且具 Trade 插座；結果歸屬 = 店舖庫存或對方實體 |

## 交換介面（Trade）

### 交易通則與商品歸屬

- **宏觀定義**：任何 NPC 含玩家，只要兩造雙方合意，皆可交易彼此背包內的物品與鎂。交易即為雙方背包之間的增減。不需要「行腳商」等特殊身份
- **店舖（特例）**：交易發生在店舖內且對象為在場的店舖 NPC 時，其中一方為**店舖庫存**（場所持有），非該 NPC 個人背包。NPC 僅在場時才具備 Trade 插座，下班或離開即喪失
- **行腳商**：非系統身份，而為湧現認知——無場所綁定、經常帶著貨移動並與人交易者，被旁人觀測為「行腳商」

### 誰可與誰交易

- 同房、具 Trade 插座、對象為實體或店舖庫存
- 依插頭插座語義：Trade 為插頭，NPC 買賣意圖為插座

### 交易流程

出價 -> 議價 -> 成交/拒絕。買方扣鎂、賣方加鎂同一原子操作。

### 借物與 Trade

- **Trade**：合意、報價／議價、鎂與物原子交割
- **借物**：不告而取；可否執行、成敗與後果依歸屬／看守／情境。獨立行為與插座

## 交易面板設計 `已收斂`

### 從對話到交易（雙入口）

| 入口 | 流程 |
|------|------|
| **直接點 Trade** | do_action Trade -> 後端回傳商品清單 -> 前端開交易面板 |
| **對話中觸發** | Talk 選「想看看你有什麼」-> 後端辨識 open_trade -> 回傳 `open_trade: true` + 可選 NPC 回覆 -> 前端開同一套面板 |

兩種入口並存，不互斥。

### 面板設計

| 面向 | 共識 |
|------|------|
| **形式** | 頁面彈窗（modal），與裝備頁、背包頁同級 |
| **陳列** | 手風琴式（accordion）：商品預設收合，點開展開詳述 + 價格 |
| **單品** | 名稱、描述、價格；可堆疊商品提供數量選擇 + 小計 |
| **資料來源** | 店舖 NPC -> 店舖庫存（場所）；行腳商 -> NPC 背包 |
| **API** | 回傳 items（含 id, name, description, price, stackable, max_stack） |
| **一致性** | 彈窗、關閉鈕、手風琴與裝備／背包頁同一套 UI 語言；無障礙對齊 |

### 後端建模建議

1. **NPC 交易意圖**：每遊戲日或每 N tick，依念紋 + 出身 + 庫存生成 1~3 筆買／賣意圖
2. **NPC-NPC 成交**：視野外 = 事件日誌；視野內 = 完整流程 + 可選推播
3. **玩家點擊 NPC 的 Trade**：回傳該 NPC 當前「想買／想賣」清單，一鍵成交
4. **市場狀況反饋**：後端維護近期成交價／成交量，供 NPC 調價；交易所大廳顯示熱門與趨勢
5. **下線角色交易策略**：玩家設定簡單策略，下線後角色變 NPC 依此參與成交
6. **機構帳本**：機構發放與據點稅等回收記帳，用於長期平衡調參
