# 探索揭露與漸進生成

> 黑格/彩格/契約層/精煉層、單調精煉原則、設施三態、觀測驅動與增量計算、局部缺席 vs 全域多樣性、觸發與 FallbackMin、黑海與版圖擴張、驗收方向、未定案事項。

## 核心名詞

| 名詞 | 意義 |
|------|------|
| **黑格** | 尚未取得確定內容；可顯示迷霧或低保真預覽，不寫入契約層 |
| **彩格** | 已揭露：地形與屬性已釘死，後續只允許精煉化補細節 |
| **契約層** | 已對玩家或模擬器承諾為真的狀態（可走/不可走、設施大類等） |
| **精煉層** | 在契約不變前提下補敘事、補子物件、補數值抖動（如礦脈品質池） |
| **黑海**（舊稱黑格海） | 新玩家首次登入時四周皆黑格的開局語境；帶有開局/孤立的敘事與系統語意 |
| **新玩家** | 新帳號首次進入遊戲者；與「同帳號第二隻角色」無關 |
| **遺落之地** | 已刪帳號的彩格區域，無主待接，不改寫已釘死契約。直至他區擴張接縫為止 |

這套概念的核心是：**一旦對玩家承諾了某個事實，就不能反悔**。只能在承諾的框架內補充細節。

## 單調精煉原則（Monotonic Refinement）

**原則**：彩格數量與邊界約束單調增加時，世界描述只應變得更**自洽、細緻**，不應與既有彩格矛盾。

- **允許**：在黑格上首次揭露時依種子 + 已揭露邊界算出結果並釘死
- **允許**：在黑格鄰域上因新路徑揭露而補齊先前未觸發的大結構（如山體邊界閉合）
- **禁止**：改寫已彩格上的契約（如把可走的變不可走、把已結清為無的改成有）

## 設施三態語意（未結/結清/存在）

避免把「還沒生成」誤當成「這裡本質上沒有」。

| 狀態 | 英文對照 | 對玩家敘事 | 生成器允許的行為 |
|------|----------|------------|------------------|
| **未結** | deferred | 尚未觀測到/尚未結算 | 下次揭露時再算；不輸出「保證無礦」的硬句 |
| **結清** | absent | 已結案：確定沒有該類設施 | 寫入契約；之後不得在同格補出該類 |
| **存在** | present | 有 | 寫入契約；細節可精煉 |

**範例（山與礦坑）**：
- 某座山體完整邊界揭露後，演算法判定**結清** -> 該山體無礦坑入口，合理
- 全域若所有山體均**結清**且無任何「礦脈在別類地形」的**存在** -> 違反全域多樣性保證，屬驗收失敗

## 觀測驅動與增量計算

後台世界並非一次算完；它**等待**玩家開出彩格，邊界條件一點一點進來，再在種子與規則下補結構。世界漸漸變清楚、變豐富。

在資訊科學上接近：
- **增量計算**、**線上演算法**（資料邊到邊算）
- 在**部分資訊**下做**約束滿足**
- 遊戲界的**戰爭迷霧驅動/揭露驅動生成**

**與「模糊計算」的區別**：數學的模糊邏輯/模糊集合（隸屬度 0~1）是「界線不清的命題怎麼算」；本專案是「還沒揭露的格子 = 資訊尚未到齊」。用 **未結 -> 結清/存在** 表達更精準，不易與模糊數學混淆。

## 局部缺席 vs 全域多樣性

**可並存的兩句話**：

1. **局部**：單一連通山塊可以沒有礦坑（或只有採石場等替代敘事）
2. **全域**：在世界種子與區域鹽值下，跨足夠大的已揭露樣本，特定可玩要素（礦坑、渡口、聚落級設施等）的出現頻率不得恆為零

**實作取向（擇一或並用，實作階段定案）**：

| 策略 | 機制 | 要點 |
|------|------|------|
| **區域配額（Quota）** | 每宏區對「礦/大聚落/主水路交會」等設下限或目標分佈 | 觸發時先查配額再擲隨機 |
| **延遲兌現（IOU）** | 早期證據不足時記「本區尚欠 1 個礦類可玩點」 | 待彩格覆蓋到合法候選後再兌現，避免「全世界山都長完才發現沒坑可填」 |
| **種子哈希** | 同一種子可重現，改種子改分佈 | 不依賴玩家順序洗結果；IOU 須在第一次需要兌現的觸發點決定位置並寫死 |

## 兩段式生成（觸發式預展開）

生成分為兩段，兼顧即時反饋與內容深度：

- **段 A**：立刻生成外框骨架（低延遲感知）
- **段 B**：異步補全聚落內功能格、坑道支脈、岸線細節
- 每次觸發最多 **1 主結果 + 1 副結果**
- 嚴苛規則只約束硬幾何/硬連通，不約束「理想豐富度」

## 觸發類型與 FallbackMin

| 觸發類型 | 硬約束（例） | FallbackMin（最小合法解） |
|----------|----------------|---------------------------|
| **路/陸連通** | 聚落對外至少一條可走聯絡 | 最小長度的單一路徑或暫時土路，標記為「可升級」 |
| **水/岸** | 渡口、碼頭須落在合法水岸幾何 | 單一岸格 + 最小連接段；敘事標「簡陋渡口」 |
| **山/障礙** | 主線不可貫穿；洞口/坑道在允許深度與邊緣帶內 | 本區 IOU 記欠、或單一邊緣洞口滿足連通；**禁止**為了美觀改牆體契約 |

**回退過嚴時**：優先產出 FallbackMin，在 debug/日誌標記 `tier: minimal`，而非整區失敗或默默空白。

回退機制確保任何情況下都能生成合法結果——寧可降級也不違反約束。

## 驗收方向（草案）

以下為方向性指標，數值待與世界尺寸、chunk 劃分一併定標：

| 指標 | 定義 |
|------|------|
| **C1** | 任意連通、已完全揭露的障礙體（山、城牆等），其「不可貫穿」與門/洞口規則與世界觀一致 |
| **C2** | 已彩格與後續揭露不衝突（單調精煉） |
| **C3** | 在「未對該要素一律結清為無」的世界線下，於足夠大的已揭露區域內，可玩要素類型不呈現全系統性缺席（以配額/IOU 驗證） |

## 黑海與版圖擴張

世界**不預設有邊**，版圖隨人口/帳號擴張而長。

### 帳號與角色（定案）

- **新帳號即新玩家**：每位新帳號首次進入遊戲，適用黑海開局
- **同帳號僅能擁有單一角色**，與既有文字版規則一致；不討論「同帳多角切換」
- **刪帳**：該帳號曾開出但尚未與大世界接軌之彩格所屬版圖，不隨刪帳而抹除地形契約；該區塊改標為**遺落之地**（無主、待接），仍遵守彩格釘死。之後可由其他玩家之區域擴張接縫，或由大世界擴張接上

### 新玩家與黑海

- 每位新帳號初次登入時，生成位置落在**黑海**：體感上四周皆迷霧/黑格，尚未與伺服器上其他已對接區域在敘事或 UI 上接通
- 黑海中的格子仍遵守 **未結 -> 彩格揭露 -> 契約釘死**；黑海不是「無規則區」，而是開局包膜

### 後台視角（版圖）

- 每多一名新帳號，世界在資料結構上多一塊**區域（chunk/宏區）**
- 這些區域在拓撲上彼此相鄰（後台知道拼圖怎麼接），但身陷黑海的玩家不知道自己離「別人的區域」多近、何時會接上
- 設計意圖：**增量世界** = 玩家帶來觀測與邊界條件，同時也帶來新地塊的種子

### 接軌條件（定案方向）

- 玩家不能永遠困在黑海而不與大世界發生關係
- **接軌**指：在邊界上生成合法出口/敘事事件/地理縫合，使可走連通至大世界/他區之已對接版圖
- 須與[[settlements|野外大地圖分級]]合流（Region、Field Node、城鎮接線規則）；**Town/City** 指野外 Node 圖上之外連與城際 hop，不等同舊 MUD 城鎮分級
- **初步傾向**：以較輕門檻為優先候選（對應「鎮級」），較重門檻為備選（對應「市級」）；Town/City 擇一或階梯，**實作前再定一版**
- 接軌須遵守單調精煉：不得推翻已揭露契約；僅在未結之黑格與接縫帶上補齊結構
- **接軌合併當下**：兩張版圖的聯外圖合併後，須**立即重算**受影響[[settlements|聚落]]的可達依附與 `effective_tier`（`on_topology_changed`）；路斷靠遊戲內修復，無系統緩衝。合併寫入須與野外 Town/City 標籤**同步收斂**；捷徑/portal 不當官方幹線者不滿足幹線計數

### 玩家體感（定案）

- 對玩家而言，無論後台是否已把某格標為彩格、是否遺落之地再接上，**體驗上都仍是「可探索的未知」**
- 不預設在 UI 上揭露「這是別人舊地圖」
- 敘事上以世界內發現、邊疆、廢土、傳送等語彙承接（細節另案）

## 未定案事項

- 宏區劃分與 chunk 邊界如何與 Hex 編輯器存檔對齊
- 「秘道/事後發現」是否允許、若允許如何不違反玩家對契約的信任
- IOU 與多人同步、讀檔重播的決定性順序
- **接軌**：Town/City 擇一或階梯之最終表；與野外大地圖分級的精確 hook（非舊城鎮區域檔之「區域數/場所數」配方）；若探索式另立聚落階級專檔，以專檔為準
- **遺落之地**：接縫優先序（大世界 vs 玩家區）、是否需最小「無主停留時間」、敘事包裝預設句庫
- 接縫演算法、多新玩家同時接軌的順序與公平性、PvE/PvP 邊界預期
