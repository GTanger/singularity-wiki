# 觀測分級與驅動

> **一句收束**：世界在暗處仍依規律活著；鏡頭照到時，才把話說得像人。

觀測分級決定了[[npc-system/decision-engine|決策引擎]]的運算深度與敘事產出層級。核心原則：**觀測只影響敘事與推理成本，不影響角色的事實是否在發生**。

---

## 觀測四層級（決策 009）

| 觀測層級 | 玩家感知 | 系統消耗 | 決策引擎行為 |
|----------|----------|----------|-------------|
| **無觀測** | 不存在 | 幾乎為零 | 數值 tick 只推排班和鎂消耗，不產出敘事 |
| **同畫面** | 人名 + 移動方向 | 極低 | 完整決策引擎運作，只輸出移動和基礎行為 |
| **注視** | 外觀、狀態描述 | 低 | 同上，額外拼裝外觀/狀態描述文案 |
| **對話** | 完整人格、記憶、情緒 | 高（LLM） | 呼叫 LLM，坍縮完整人格與記憶 |

**原則**：GPU 只在「對話」層才燒。其餘三層純文字、純邏輯，不需要模型。NPC↔NPC 後台對話的觸發時機應與觀測層級掛鉤——非觀測之地的活人與機器人何異？

## 觀測圈與驅動機制

### 觀測圈定義

- **觀測圈** = 有玩家在的房間 + 鄰房（一階鄰接）
- 程式：`buildActiveRoomIDs(...)` 建構觀測圈 room ID 集合

### 有人觀測

- `TravelerManager.Tick(..., activeRoomIDs)` 只對「當前房間 ∈ 觀測圈」的 NPC 做完整尋路／Decide／移動與到達後行為
- 只對這些移動發敘事
- NPC 間 AI 對話僅在有玩家的房間觸發（見[[npc-system/interaction|NPC 間交互行為]]）

### 無人觀測

- 觀測圈為空，不跑 Tick（不跑九萬腦）
- 改跑 `RunUnobservedWorldTick(database, roomGraph, gameHour, maxNPCs)`：
  - **有排班的 NPC**：依 gameHour 決定目標（在班→work_room，下班→rest_room），**朝目標房走一步**（FindPath 取第一步）。不會被當成「隨機閒晃」或半夜被拉出門
  - **無排班的 NPC**：抽樣施加一項抽象效果（加鎂／採集／求職／隨機鄰房），不發敘事
- 每輪抽樣最多 N 個 NPC（如 50）做輕量模擬

### 規模直觀

- **有人觀測**：僅觀測圈內 NPC 跑完整腦 + 移動（數量 ≈ 觀測圈房數 × 每房 NPC，遠小於九萬）
- **無人觀測**：排班者只做「朝班表目標走一步」，無排班者四效果擇一

## 行程約束（決策 009 核心）

### 五條硬規則

1. **單一世界時鐘**：時間全域推進，觀測分級只改變敘事與推理成本
2. **行程優先於擲骰**：上班、在崗、睡眠等為硬約束，後台模擬不可違背
3. **在崗由權威資料決定**：NPC 是否出現在職場，由 assignment/排班/店舖狀態的決定性規則解析，不以隨機決定
4. **雲端/LLM 定位**：優先用於玩家高顯著度互動；非玩家格以規則、模板、摘要 log 為主
5. **認知與敘事對齊**：視線外的人事物可合理視為節律可見、內心不可見

### 蕗易沙店員範例

玩家走進蕗易沙時，怎麼保證店員在場？

- **權威來源**：店員與店面的 assignment 決定：在班時段內，其合法位置必須包含店面
- **擲骰用在哪裡**：在已滿足「人在店內、在班」之後，才骰微動作、閒置 emote 等枝節
- **不可用骰子決定「店裡有沒有店員」**——除非世界設定允許閉店/請假等明確狀態
- **玩家進房 = 觀測坍縮**：以當前遊戲時間 + 排班 + 合法位置做一次決定性解析

### 設計者筆記

> 現實裡的人也是依固定節律在生活。自己看不到的時候，並沒有在腦裡為他們逐句生成對白與內心戲。視線外的他人，對「我」而言，與依規則運轉的機器人/黑箱並無二致——直到再次進入觀測為止。

## 觀測實作狀態

| 項目 | 狀態 |
|------|:----:|
| 觀測圈篩選（`buildActiveRoomIDs`） | ✅ |
| 無觀測世界 tick（`RunUnobservedWorldTick`） | ✅ |
| 排班者依 gameHour 走一步 | ✅ |
| 無排班者抽象效果（加鎂/採集/求職/隨機鄰房） | ✅ |
| 觀測層級對應算力（無觀測不跑敘事/不跑 LLM） | ✅ |
| 表面行為觀測（`current_activity` 欄位） | ✅ |
