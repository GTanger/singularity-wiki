# 技能、裝備與背包

> 全機率 Tick 運算的戰鬥系統、MUD 式 20 槽位裝備、古典負重制背包。三個分頁共同構成詞盤系統的「出水口」。

## 技能分頁規格

### 核心原則

- **全機率 Tick 運算**：無主動施放。後端每 Tick 依權重擲骰自動演算，前端僅呈現富文字敘事 Log。
- **內定外動**：內盤詞元煉化入體後極難置換（絕對基底）；流派切換靠更換裝備與運轉功法。
- **田忌賽馬**：輸贏靠配置與策略，不靠操作。低傷招式若能在環境留下關鍵詞元引發連鎖，即為無價之寶。

### 廢除主被動區分

所有招式（無論來源）皆為「機率觸發」，由後端依權重每 Tick 擲骰決定。玩家不手動點擊施放。

### 觸發權重公式（完整版）

```
觸發權重 = SkillObject.基礎觸發率
         × 熟練度係數（初窺 0.6 / 小成 0.8 / 大成 1.0 / 圓滿 1.2）
         × 持物適配度（手持長劍 → 劍系高、拳系低）
         × 心法共鳴係數
         × 有效維度加權（體敏氣依招式類型取對應維度）
```

### 效果公式

```
實際效果 = SkillObject.基礎效果 × 三軸係數（能階/時脈/相位）
```

三軸係數來自[[character-system|人物屬性系統]]的念紋三軸：

- **能階 (Amplitude)**：影響傷害規模（高能階 = 爆發力強）
- **時脈 (Frequency)**：影響觸發節奏（高時脈 = 連擊傾向）
- **相位 (Phase)**：影響連鎖反應的散佈模式

同一招在不同念紋的人手裡效果截然不同——「萬人萬相」在戰鬥端的延伸。

### 資源檢定與反噬

每個 SkillObject 帶有資源消耗（`cost`：氣力、體力等）。Tick 擲骰抽中某招後，系統檢查當前資源：

- **資源充足**：正常施放
- **資源不足**：進入 A/B 雙軌判定——
  - **(B) 反噬（高機率）**：強制施放，不足的資源以 **1:2** 比例直接扣除氣血（HP）。Log 產出紅色警告敘事（如「氣力乾涸，強行催動『霸皇斬』致氣血逆流」）
  - **(A) 力竭（低機率）**：招式施放失敗（Fizzle），本 Tick 無動作。Log 產出灰色提示（如「後繼無力，攻勢化為烏有」）

> A/B 機率比例（如 B:A = 7:3）為框架預留，數值後定。

**設計意圖**：玩家無法在戰鬥中干預，但戰後可從 Log 中檢討——若反噬頻繁導致陣亡率高，迫使玩家重新配置招式池。這是放置戰鬥的核心養成毒性。

### 語境殘留（Context Residue）

招式觸發後，核心詞元殘留於戰場（持續數 Tick）。後續 Tick 出現相容詞元 → 語意連鎖反應（如 [火]+[風]=爆燃）。低傷招式可作為「引信」鋪設環境伏筆。

**相位與連鎖散佈模式**：

| 相位傾向 | 散佈模式 | 說明 |
|----------|----------|------|
| 秩序（Phase 趨近 +1.0） | 精準單體 | 傷害鎖定主目標，數值穩定 |
| 中性（Phase 趨近 0） | 一般散佈 | 依預設規則散佈 |
| 混沌（Phase 趨近 -1.0） | 房間 AOE | 傷害在敵方陣營內隨機彈射，數值大起大落。**絕不波及自身與友方** |

> 具體係數與散佈公式為框架預留，待戰鬥引擎實作時補齊。

### 功法系統

#### 無掛載上限：動態權重引擎

**不設功法掛載數量上限**。所有習得武學永遠存在於招式池，靠動態權重自然淘汰。

**動態權重四因子**：

| 因子 | 說明 |
|------|------|
| **熟練度係數** | 勤練則權重高，荒廢則權重低 |
| **持物適配度** | 當前持物（`hold_l`/`hold_r`）與招式所需器物的匹配。手持長劍→劍系高、空手系低；空手時徒手系最大化 |
| **心法共鳴** | 當前運轉心法對相容技法提供全域觸發率加成。頂級心法共鳴廣，平民心法窄 |
| **有效維度** | 體敏氣依招式類型取對應維度加權 |

**舉手投足皆武器**：練了足技、關節技、擒拿術且熟練度高，空手下全數高權重進池。拔出長劍則劍系浮現、徒手系沉底。

#### 心法唯一

心法為能量流轉根基，同時僅運轉一套。切換心法 = 切換全域共鳴底色，招式池瞬間重算。外功不限數量。

#### 頂級功法 = 複合矩陣

一本頂級功法（如《天極霸皇劍》）內含劍陣、步法、指法、心法等子類。`martial_matrix` 定義各子類權重占比。劍被打飛後步法、指法子類仍可觸發——手中無劍，心中有劍。

#### 功法星位共鳴（反向優化）

長期修練某功法，對關聯星位產生反向優化（降低阻力、提升詞元權重等）。功法類型以真實武學命名（劍法、拳術、指法、身法、心法），不使用系統面泛稱。

- **`[微循環]`**：僅走綠點表層的功法，無星位共鳴
- **`[大循環]`**：路徑經橘→藍→綠的功法，具星位共鳴效果

#### 熟練度

| 等級 | 名稱 | 觸發率係數 | 說明 |
|------|------|-----------|------|
| 0 | **未學** | — | 未習得，不進池 |
| 1 | **初窺** | ×0.6 | 剛習得 |
| 2 | **小成** | ×0.8 | 基本掌握 |
| 3 | **大成** | ×1.0 | 完整發揮 |
| 4 | **圓滿** | ×1.2 | 爐火純青 |

**提升方式**：累計使用次數（戰鬥中該功法招式被觸發次數達門檻即升級）。數值後定。

### UI 三區塊

1. **運轉功法**：心法（僅一套，全域共鳴底色）+ 所有已習得外功（不限數量，依熟練度排序）
2. **實戰招式池**：當前配置下有機率觸發的所有招式（僅[[sentence-crafting|二階以上共振]] + 功法自帶）
3. **語境推演**：戰前推演最可能殘留的詞元變數與連鎖反應。每次換裝備/切心法時重算

### UI 範例

```
【 運轉功法 】
▣ 心法：《混元吐納術》 (熟練：圓滿)  [大循環]
  └ 星盤滋養：為全星盤提供穩定氣脈底噪。
────────
◆ 劍法：《天極霸皇劍》 (熟練：小成)  [大循環]
  ├ 矩陣：劍陣 50% ｜ 步法 20% ｜ 指法 15% ｜ 心法 15%
  └ 星位共鳴：引動 [天極] 主樞，提升該星系攻擊性詞元威能。
◆ 拳術：《莊稼漢拳腳》 (熟練：初窺)  [微循環]
  └ (無星位共鳴)
```

```
【 實戰招式池 】
⚔ 霸皇斬 ｜ 觸發率：極高 (受 劍法熟練 增幅)
  ├ 來源：劍法《天極霸皇劍》
  └ 描述：牽動天極星位動能，造成巨量物理傷害。
```

```
【 語境推演 】
◆ 環境干涉傾角：
  └ 高頻殘留：[ 鋒 ] (占比 45%) ｜ [ 火 ] (占比 30%)
◆ 預期連鎖反應：

```

## 後端資料結構

### 功法結構（SkillManual）

| 欄位 | 類型 | 說明 |
|------|------|------|
| `id` | TEXT | 功法唯一 ID |
| `name` | TEXT | 功法名稱（如「天極霸皇劍」） |
| `slot_type` | TEXT | `inner`（心法）或 `outer`（外功） |
| `martial_matrix` | TEXT/JSON | 武學子類權重矩陣。簡單功法可為單一類型 |
| `circulation` | TEXT | `micro`（微循環）或 `macro`（大循環） |
| `path_nodes` | TEXT/JSON | 功法路徑之節點 ID 序列（路徑定義） |
| `resonating_nodes` | TEXT/JSON | 此功法關聯的星位節點 ID 陣列（共鳴對象） |
| `resonance_effect` | TEXT | 對星盤的優化效果描述 |
| `moves` | TEXT/JSON | 附帶招式清單（含基礎觸發權重、`cost`、`residue_tokens`、`required_weapon_type`） |

**`martial_matrix` 範例**：

```json
// 頂級複合功法
{"劍法": 0.50, "步法": 0.20, "指法": 0.15, "心法": 0.15}

// 平民單一功法
{"拳術": 1.0}
```

矩陣中的子類權重影響持物適配度計算——劍被打飛後劍法子類歸零，但步法、指法子類仍可觸發。

### SkillObject 結構

招式池中的原子單位。煉化入竅或習得功法時編譯產出，戰鬥時僅讀取。

| 欄位 | 類型 | 說明 |
|------|------|------|
| `id` | TEXT | 招式唯一 ID |
| `name` | TEXT | 招式名稱（功法自帶為固定名、系統判名為自動萃取 2~4 字） |
| `source_type` | TEXT | `manual`（功法自帶）/ `inner_resonance`（內盤造句）/ `outer_resonance`（裝備造句） |
| `source_id` | TEXT | 來源功法 ID 或造句 ID |
| `resonance_tier` | INT | 共振階層：2（語意共振）或 3（純粹共振）；功法自帶填 0 |
| `sub_type` | TEXT | 招式所屬子類（劍法、拳術、步法、指法……），用於持物適配度計算 |
| `required_weapon_type` | TEXT/NULL | 需要的持物類型（如 `"鋒刃"`）；null 表示徒手可用 |
| `base_trigger_rate` | FLOAT | 基礎觸發率（0.0~1.0） |
| `cost` | JSON | 資源消耗（如 `{"氣力": 50}` 或 `{"體力": 20}`） |
| `base_effect` | JSON | 基礎效果結構（傷害值、效果類型、影響維度等） |
| `residue_tokens` | JSON | 觸發後殘留於環境的詞元清單（如 `["火","鋒"]`） |
| `description` | TEXT | 招式敘事描述 |

### 戰鬥 Log 原子結構

後端每 Tick 產出的單條 Log，為前端渲染富文字的唯一資料契約。支援單體與全房 AOE。

| 欄位 | 類型 | 說明 |
|------|------|------|
| `tick` | INT | 當前 Tick 序號 |
| `actor` | TEXT | 施招者 entity_id |
| `targets` | JSON | 受擊者 entity_id **陣列**（`["npc_001"]` 或 `["npc_001","npc_002","npc_003"]`） |
| `move_id` | TEXT | 觸發的 SkillObject ID |
| `move_name` | TEXT | 招式名稱 |
| `source` | TEXT | 來源（功法名或造句描述） |
| `result` | TEXT | 結果（命中/閃避/格擋/反噬/力竭……） |
| `damage` | INT | 造成傷害（0 = 未命中或非傷害招；反噬時為自傷值） |
| `resource_cost` | JSON/NULL | 實際消耗（如 `{"氣力": 50}` 或反噬時 `{"氣血": 100}`） |
| `residue_added` | JSON | 本次新增至環境的殘留詞元 |
| `chain_triggered` | TEXT/NULL | 觸發連鎖反應名稱；否則 null |
| `narrative` | TEXT | 富文字敘事（前端直接渲染） |

### 戰鬥引擎每 Tick 執行順序

1. **擲骰選招**：依完整觸發權重公式從 Combat Pool 加權抽取
2. **資源檢定**：檢查 `cost` 是否滿足，不足進入 A/B 雙軌判定
3. **效果計算**：`基礎效果 × 三軸係數`，相位決定散佈模式
4. **語境更新**：將 `residue_tokens` 加入環境殘留清單，檢查連鎖觸發條件
5. **產出 Log**：填充 Log 原子結構，推送前端

- **NPC 對等**：NPC 互打邏輯與玩家打怪完全相同（同一套 Pool 對撞），支撐萬名 NPC 背景運算
- **語境殘留**：維護戰場環境的詞元殘留清單（每條帶 TTL），每 Tick 檢查連鎖觸發條件
- **房間制 AOE**：混沌相位連鎖或特定群攻招式可命中同房多個目標（`targets` 陣列），致敬 MUD 全房叫殺

### 裝備結構對接

更換 `equipment_slots`（20 個槽位）會即時改變持物適配度，招式池中各招的觸發權重瞬間重算。拔劍→劍系浮現、徒手系沉底；卸劍→反之。內盤詞元不動、外盤（裝備+功法）可換，即「內定外動」。

## 技能實作優先序

1. **第一版（骨架）**：前端三個區塊佔位文字
2. **第二版（功法系統）**：功法 schema（含 `martial_matrix`）、功法習得、心法切換、熟練度框架
3. **第三版（戰鬥引擎 MVP）**：Tick RNG Combat、SkillObject 編譯、動態權重引擎、資源檢定（A/B 反噬）、戰鬥 Log 產出
4. **第四版（語境殘留）**：殘留機制、連鎖反應表、相位散佈模式、語境推演計算

### 已知斷點

- **功法藍圖獨立規格**：路徑節點序列、習得條件、NPC 功法表、`martial_matrix` 標準子類清單
- **持物適配度對照表**：哪些 `sub_type` 對應哪些 `required_weapon_type`
- **連鎖反應表**：語境殘留的組合觸發條件（如 `[火]+[風]=爆燃`）
- **A/B 反噬比例**：反噬（B）與力竭（A）的機率比、HP 換算比例
- **語境推演計算時機**：每次換裝備/切心法即重算

## 裝備分頁規格

### 20 個槽位（完整代碼對照）

| 2 | `face` | 【面甲】 | 頭面 |
| 3 | `neck` | 【護頸】 | 頭面 |
| 4 | `undershirt` | 【襯衣】 | 軀幹 |
| 5 | `inner_armor` | 【內甲】 | 軀幹 |
| 6 | `body` | 【掛鎧】 | 軀幹 |
| 7 | `cloak` | 【披風】 | 軀幹 |
| 8 | `shoulder` | 【肩鎧】 | 雙臂 |
| 9 | `arm` | 【護臂】 | 雙臂 |
| 10 | `wrist` | 【護腕】 | 雙臂 |
| 11 | `hand` | 【掌套】 | 雙臂 |
| 12 | `waist` | 【腰鎧】 | 腰足 |
| 13 | `legs` | 【襯褲】 | 腰足 |
| 14 | `leg_armor` | 【腿鎧】 | 腰足 |
| 15 | `feet` | 【護靴】 | 腰足 |
| 16 | `ring_l` | 【左指】 | 飾物 |
| 17 | `ring_r` | 【右指】 | 飾物 |
| 18 | `trinket` | 【佩掛】 | 飾物 |
| 19 | `hold_l` | 【左持】 | 持物 |
| 20 | `hold_r` | 【右持】 | 持物 |

**【持】位規則**：左右完全對等，任何可持物品皆可放入任一側。無主副手之分，盾可為主武器，雙盾流合法。

### 設計原則

- **視圖分離**：裝備分頁只顯示穿了什麼；維度加成顯示在【狀態】，裝備技能顯示在【技能】
- **白板裝備**：無念物質，受游離輻射影響數值不穩；附詞 = 附上有念生物頻率，阻隔輻射使裝備穩定

白板裝備透過[[three-fork|裝備附魔]]獲得穩定性與額外效果。附魔詞元與穿戴者內盤相容時觸發共鳴。

### 跨分頁連動

| 產出類型 | 顯示位置 | 格式 |
|----------|----------|------|
| 維度加成（體質/氣脈/靈敏） | 【狀態】分頁 → 維度行 | `體質 11 (+2)` |
| 裝備技能 | 【技能】分頁 | `「格擋」 (來自：玄木圓盾)` |

**男性初始套裝**：

| 槽位 | 物品 ID | 物品名稱 |
|------|---------|----------|
| 【掛鎧】`body` | `starter_body_m` | 粗布鎧甲 |
| 【襯褲】`legs` | `starter_legs_m` | 粗布長褲 |
| 【護靴】`feet` | `starter_feet_m` | 草鞋 |

**女性初始套裝**：

| 槽位 | 物品 ID | 物品名稱 |
|------|---------|----------|
| 【掛鎧】`body` | `starter_body_f` | 素布鎧甲 |
| 【襯褲】`legs` | `starter_legs_f` | 布裳 |
| 【護靴】`feet` | `starter_feet_f` | 布鞋 |

共 6 件靜態物品（另含 3 個空槽：襯衣、內甲、腿鎧），**無屬性加成、無詞位**（最低階白板裝）。後端以 `StarterEquipment(gender)` 回傳初始 JSON。

### 裸奔判定

- **門檻**：`body` 與 `legs` 任一為空 → 「衣不蔽體」
- **判定函式**：後端 `IsNaked(equipmentSlots string) bool`
- **後果**（規格預留）：同房 NPC/玩家敘事 log「投以異樣眼光」；城鎮區域遠期觸發警衛逮捕事件

### 後端資料結構

- **entities 表**：`equipment_slots` 欄位（TEXT/JSON），預設 `{}`
- **Item 結構**：每件 Item 含 `attributes` Map（維度加成）與 `tokens` List（詞位與已鑲嵌詞元）
- **計算邏輯**：
  - `CalculateEffectiveAttributes()`：基礎值（SoulSeed 展開）+ 遍歷 20 槽位裝備加成
  - `GetActiveSkills()`：收集星盤（內盤）造句技能 + 裝備（外盤）技能，統一回傳前端

### 裝備實作優先序

1. **第一版（骨架）**：前端 20 槽位 + 初始裝備。後端 `equipment_slots` 欄位 + `items` 表
2. **第二版（物品系統）**：物品生成、背包、掉落
3. **第三版（穿脫互動）**：穿脫指令、屬性結算、技能分流

## 背包規格

### 核心機制

- **古典 MUD 負重制**：無格子限制，背包為 flat list，唯一限制為負重
- **最大負重** = `體質 × 10`
- **超重懲罰**：不可移動（第一版僅此懲罰）
- **丟棄即掉落**：物品從背包移除，進入當前房間（待實作）
- **UI 位置**：頂欄獨立「背包」按鈕，點擊開啟獨立彈窗（不在人物彈窗內）

### 物品分類

| item_type | 說明 | 可堆疊 | 範例 |
|-----------|------|--------|------|
| `currency` | 鎂（實體貨幣，有面額，佔重量） | 是 | 鎂幣(1)、鎂鈔(10)、鎂錠(10000) |
| `equipment` | 可穿戴至 20 槽位 | 否 | 墨晶長劍、粗布短褂 |
| `crystal` | 詞元結晶（提出前的儲存態） | 同 `source_class` + 同 `source_node_id` + 同品階 | 甲級山礦結晶（蒼嶺）×3 |
| `consumable` | 使用後消失 | 是 | 丹藥、食物 |
| `material` | 採集材料（剝名前） | 同 `source_class` + 同 `source_node_id` | 蒼嶺礦石 ×5 |
| `misc` | 其他（任務物等） | 是 | 破碎器皿 |

### 堆疊規則

- **可堆疊**：`item_id` 相同且 `stackable = 1` → 合併為 `{item_id, qty}`
- **不可堆疊**：裝備（每件可有獨立鑲嵌）
- **結晶堆疊 = 純 UI 壓縮**（2026-04-08 定案）：不影響操作語義，提出/剝名時仍逐顆處理
- **裸詞元不可收納**：結晶提出後不進背包，須即時使用（[[three-fork|入竅/附魔/疊煉/鑄鎂]]）

### 鎂（實體貨幣）

鎂是實體物品，佔重量，有面額。

| item_id | 名稱 | 面額（鎂） | 單件重量 | stackable |
|---------|------|-----------|---------|-----------|
| `mg_coin` | 鎂幣 | 1 | 0.01 | 是 |
| `mg_note` | 鎂鈔 | 10 | 0.005 | 是 |
| `mg_ingot` | 鎂錠 | 10,000 | 1.0 | 是 |

items 表額外欄位 `denomination INTEGER` 記錄面額。

第一版鎂仍以 entities 表 `magnesium` 欄位存放（整數），不進背包。待 V2 拆分為面額物品入背包。

### 後端資料結構

**items 表擴充**：

| 欄位 | 類型 | 說明 |
|------|------|------|
| `weight` | REAL | 單件重量（預設 0） |
| `item_type` | TEXT | 物品分類（預設 'misc'） |
| `stackable` | INTEGER | 0=不可堆疊，1=可堆疊（預設 0） |

**entities 表新增**：

| 欄位 | 類型 | 說明 |
|------|------|------|
| `inventory` | TEXT | JSON 陣列 `[{"item_id":"xxx","qty":1}]`（預設 '[]'） |

**負重計算**：

```
current_weight = Σ (item.weight × entry.qty)  for each entry in inventory
max_weight = entity.vit × 10
```

### 背包實作優先序

1. **第一版（骨架）**：頂欄按鈕 + 彈窗 UI + 後端回傳空背包
2. **第二版（物品系統）**：物品掉落、拾取、丟棄、房間物品
3. **第三版（穿脫互動）**：從背包穿上裝備、脫下裝備進背包
4. **第四版（鎂實體化）**：鎂拆為面額物品，從 `magnesium` 欄位遷移至 `inventory`
